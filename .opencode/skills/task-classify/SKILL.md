# Классификация задачи руководителя

## Входные данные
Текст задачи из чата руководителя.

## Алгоритм классификации

### Шаг 1 — Определи тип

**QUICK** (< 15 мин) — задачи, которые можно сделать «на ходу»:
- Триггеры: согласовать, апрув, подтвердить, глянуть, ответить, подписать, резолюция
- Примеры: «апрувнуть PR Петровой», «ответить HR по вакансии», «подписать заявку на GPU»

**COMMUNICATION** (15–60 мин) — задачи с участием других людей:
- Триггеры: позвонить, встреча, обсудить, созвон, написать, переговорить, стендап, демо, 1:1, one-on-one
- Примеры: «позвонить Краснову по данным», «встреча с заказчиком по шихте», «1:1 с Сидоровым»

**DEEP_WORK** (> 60 мин) — задачи, требующие сосредоточенности:
- Триггеры: подготовить, проанализировать, разработать, написать отчёт, ревью, презентация, стратегия, архитектура, код-ревью, планирование, декомпозиция
- Примеры: «подготовить презентацию по шихте», «код-ревью ML-pipeline», «анализ ТЗ от цеха 3»

### Шаг 2 — Оцени длительность

| Тип | Диапазон | По умолчанию |
|-----|----------|-------------|
| QUICK | 5–15 мин | 10 мин |
| COMMUNICATION: звонок | 10–20 мин | 15 мин |
| COMMUNICATION: встреча | 30–60 мин | 45 мин |
| COMMUNICATION: стендап | 15–30 мин | 20 мин |
| DEEP_WORK: код-ревью | 60–120 мин | 90 мин |
| DEEP_WORK: презентация | 90–180 мин | 120 мин |
| DEEP_WORK: анализ ТЗ | 60–120 мин | 90 мин |
| DEEP_WORK: отчёт | 120–240 мин | 150 мин |

### Шаг 3 — Определи приоритет

```
P0 — содержит: блокирует, срочно, production, авария, инцидент
P1 — содержит: дедлайн скоро, заказчик ждёт, блокер для коллеги
P2 — содержит: важно, стратегическое, нужно на этой неделе
P3 — содержит: когда будет время, техдолг, улучшение, nice to have
```

## Формат вывода

```
Тип: <QUICK / COMMUNICATION / DEEP_WORK>
Оценка: ~<X> мин
Приоритет: <P0 / P1 / P2 / P3>
Обоснование: <почему такой тип и приоритет>
```
