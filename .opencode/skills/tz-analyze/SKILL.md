# Анализ технического задания

## Процесс анализа

### Шаг 1 — Понять суть
Извлечь из ТЗ: цель проекта, бизнес-задача, ожидаемый результат.

### Шаг 2 — Определить сложность

| Уровень | Часы | Характеристики |
|---------|------|---------------|
| S | < 40ч | Один источник данных, знакомая задача, нет интеграции |
| M | 40–120ч | 1–2 источника, типовая модель, базовая интеграция |
| L | 120–320ч | Несколько источников, сложная модель, интеграция в production |
| XL | > 320ч | R&D, много зависимостей, новая предметная область |

### Шаг 3 — Декомпозировать
Разбить на подзадачи. Типовая декомпозиция DS-проекта:
1. Сбор и анализ данных (EDA)
2. Feature engineering
3. Обучение и валидация модели
4. Интеграция / деплой
5. Документация и передача

### Шаг 4 — Оценить по PERT
Для каждой подзадачи: O / M / P → PERT = (O + 4M + P) / 6

### Шаг 5 — Выявить риски
Типичные для металлургии:
- Качество данных с датчиков
- Зависимость от IT/OT отделов
- Неоднозначность требований
- Модель не достигает метрики
- Интеграция в production

### Шаг 6 — Найти аналоги
Поиск в `data/projects.json` по ключевым словам. Показать план/факт для калибровки.

### Шаг 7 — Рекомендовать команду
По `data/team.json` и `data/workload.json`: кто подходит по навыкам и свободен.

## Формат вывода

Структурированный отчёт с числами, таблицами и рекомендациями (см. шаблон в tz-analyst агенте).
