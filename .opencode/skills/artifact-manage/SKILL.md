# Управление артефактами

## Создание артефакта

### Входные данные
Свободный текст от руководителя + контекст (текущий проект, недавние упоминания).

### Алгоритм

1. **Определи тип:**

| Триггер в тексте | Тип | Директория |
|---|---|---|
| ТЗ, техзадание, задание на разработку | `tz` | `data/artifacts/tz/` |
| заметка, запиши, зафиксируй, пометь | `note` | `data/artifacts/notes/` |
| встреча, созвон, митинг, протокол | `meeting_notes` | `data/artifacts/notes/` |
| решение, выбрали, архитектура, подход | `architecture_decision` | `data/artifacts/notes/` |
| отчёт, сводка, дайджест | `report` | `data/artifacts/reports/` |
| модель, model card, карточка модели | `model_card` | `data/artifacts/reports/` |
| EDA, исследование данных | `eda_report` | `data/artifacts/reports/` |

2. **Извлеки метаданные:**
   - title — краткий заголовок (< 80 символов)
   - project_id — по ключевым словам, людям, контексту
   - tags — из `ontology.json → tags_taxonomy`
   - related_people — упомянутые люди
   - priority — по контексту (P0–P3, по умолчанию P2)

3. **Сгенерируй ID:**
   - Формат: `<type>-<NNN>` (трёхзначный номер)
   - Следующий номер: max(existing) + 1 по index.json

4. **Создай файл** по шаблону типа (см. ниже)

5. **Обнови index.json** — добавь запись

6. **Покажи подтверждение:**

```
Артефакт создан:
├── Тип: <type>
├── ID: <id>
├── Файл: <path>
├── Проект: <project>
├── Теги: <tags>
├── Чеклист: 0/<N> пунктов
└── Статус: draft

Открыть для редактирования? Или всё верно?
```

## Поиск артефактов

### Синтаксис запросов

| Запрос пользователя | Фильтр |
|---|---|
| «найди ТЗ» | type = tz |
| «заметки по проекту X» | type = note, project_id ~ X |
| «что было про Краснова» | related_people contains krasnov |
| «все P0 артефакты» | priority = P0 |
| «открытые чеклисты» | checklist_done < checklist_total |
| «за последнюю неделю» | created_at >= now - 7d |
| «отчёты по качеству» | type = report, tags contains quality |

### Ранжирование результатов
1. Точное совпадение project_id или related_people → вес ×3
2. Совпадение тегов → вес ×2
3. Совпадение в title/summary → вес ×1
4. Свежие документы приоритетнее

## Обновление чеклистов

При запросе «отметь пункт N в <артефакт>»:
1. Найди файл по id или title
2. Найди N-й чекбокс (`- [ ]`)
3. Замени на `- [x]`
4. Пересчитай `checklist_done` в frontmatter и index.json
5. Если все done → предложи статус `completed`

## Шаблоны

### ТЗ (tz)
```markdown
---
id: "tz-NNN"
type: tz
title: ""
# ... frontmatter
---
# <Title>

## Цель
<Бизнес-задача, зачем нужен проект>

## Исходные данные
- Источник: <откуда>
- Формат: <csv/api/db>
- Объём: <N записей, период>
- Качество: <оценка>

## Требования к результату
- Целевая метрика: <F1/MAE/...> > <значение>
- Формат выхода: <API/dashboard/report>
- Интеграция: <куда встраивается>

## Ограничения
- <ограничение 1>

## Этапы
- [ ] EDA и анализ данных
- [ ] Feature engineering
- [ ] Обучение модели
- [ ] Валидация на hold-out
- [ ] API / интеграция
- [ ] Документация и передача
```
