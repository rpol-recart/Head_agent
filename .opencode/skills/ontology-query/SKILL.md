# Запросы к онтологии

## Источник данных
`data/ontology.json` — граф знаний DS-отдела.

## Типы запросов

### 1. Поиск по сущности
«Кто такой <имя>?» / «Что за проект <название>?»

→ Найти в `entities`, показать все связи из `relationships`.

```
Краснов Виктор:
├── Роль: Начальник цеха №3, Производство
├── Заказчик: Предиктивное качество проката (pred_quality)
├── Управляет: Литьё (Цех №3)
└── Артефакты: tz-001, note-003
```

### 2. Граф связей
«Кто работает с <X>?» / «Что связано с <Y>?»

→ Обход графа relationships в обе стороны (from/to).

### 3. Поиск по домену
«Все проекты по CV» / «Кто занимается NLP?»

→ entities.projects where domain = X + relationships where type = lead/contributor.

### 4. Источники данных
«Откуда данные для <проект>?»

→ relationships where type = consumes_data AND from = project.

### 5. Технологический стек
«Какие технологии в проекте X?» / «Кто использует PyTorch?»

→ entities.technologies where used_in contains X.

## Обновление онтологии

### Когда обновлять
- Руководитель упомянул нового человека → добавить в `entities.people.external`
- Новый проект → добавить в `entities.projects`
- Новая связь (человек↔проект) → добавить в `relationships`
- Новая технология → добавить в `entities.technologies`
- Новый тег → добавить в `tags_taxonomy`

### Формат обновления
Показать руководителю что изменилось:
```
Онтология обновлена:
+ Добавлен: <entity_type> "<name>"
+ Связь: <from> → <to> (тип: <type>)
```

## Принципы
- Не удалять данные, только добавлять/обновлять
- При конфликтах — спросить руководителя
- Инкрементировать `_meta.version` при каждом обновлении
